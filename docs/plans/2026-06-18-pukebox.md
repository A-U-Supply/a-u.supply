# Puke Box: public page + search-engine ingest

**Branch:** `feat/pukebox` → PR TBD
**Status:** plan-only

## Goal

Give the daily AI-generated MIDI jukebox a first-class home at `https://a-u.supply/pukebox` backed by the app's own search engine, so it stops depending on the broken legacy-repo → server webhook chain.

## Background

`/puke-box.html` (hyphenated) is served from `/srv/legacy-site` via the fallback middleware at `main.py:690`. New MIDI is generated by the `daily-midi` GH Action in `A-U-Supply/ausupply.github.io`, archived by the `puke-box.yml` action (scrapes Slack `#midieval`, writes `puke-box/<entry>/` + `manifest.json`), then a GitHub webhook is supposed to hit `/hooks/legacy` to `git pull` `/srv/legacy-site`.

Two propagation breaks (see investigation, 2026-06-18):
1. **No webhook** is registered on `ausupply.github.io` — `gh api .../hooks` returns empty.
2. The webhook's `git pull` (`main.py:941`) fails with `fatal: detected dubious ownership` and stderr is sent to `/dev/null`, so it fails silently. `/srv/legacy-site` is frozen at 2026-05-16 while the repo is at 2026-06-15.

Generation is fine; only propagation is broken. This plan sidesteps the whole chain by ingesting directly from Slack into our search engine.

## Approach

Mirror the **`samples-bored`** pattern (`docs/plans/2026-05-28-samples-bored.md`, `scripts/index_samples.py`, `search_client.py:39`): a dedicated Meilisearch index for a curated named collection of bot-generated audio, routed via `output_index`. Three pieces:

1. **Ingest** — a new `server/pukebox_ingest.py` reads Slack `#midieval`, parses the Daily MIDI message, downloads the 4 MIDI stems, synthesizes an OGG preview, and creates one `MediaItem` per entry routed to the `puke-box` index. Scheduled alongside `slack_scraper`.
2. **Index** — a dedicated `puke-box` Meilisearch index with musical metadata (scale, root, tempo, chords) as first-class searchable/filterable attributes.
3. **Page** — `src/pages/pukebox.astro` (clean URL, Astro default) mounting a Svelte jukebox island that reads from a public read endpoint. Legacy `/puke-box.html` keeps working untouched via the fallback middleware.

## Data model

One `MediaItem` per daily entry:

| Field | Value |
|-------|-------|
| `media_type` | `"audio"` (the OGG preview) |
| `file_path` | `audio/YYYY-MM/<entry-id>-preview.ogg` under `SEARCH_MEDIA_DIR` |
| `output_index` | `"puke-box"` |
| `sha256` | of the OGG |
| `sources` | one `MediaSource` (`source_type="slack_file"`, channel `midieval`, message text, thread ts) |

New extension table `MediaPukeBoxMeta` (mirrors `MediaAudioMeta` / `MediaSessionMeta` as a per-item 1:1 extension):

| Column | Type | Notes |
|--------|------|-------|
| `media_item_id` | FK PK | 1:1 with `media_items` |
| `entry_id` | String | `YYYY-MM-DD-HHMMSS` (the Slack ts) |
| `scale` | String | e.g. `Lydian` |
| `root` | String | e.g. `C#` |
| `tempo` | Integer | BPM |
| `chords` | String (JSON) | chord list |
| `description` | String | the bot's one-liner |
| `melody_instrument` | Integer | General MIDI program |
| `temperature` | Float | RNN temperature |
| `midi_paths` | String (JSON) | `{"melody": "...", "drums": "...", "bass": "...", "chords": "..."}` relative to `SEARCH_MEDIA_DIR` |

`MediaAudioMeta` is still populated for the OGG (duration, sample rate) by the existing extraction pipeline.

## Index routing (`server/search_client.py`)

- `PUKE_BOX_INDEX = "puke-box"` constant, added to `all_indexes` in `configure_indexes()`.
- `_index_for_media_item()`: items with `output_index == "puke-box"` → `PUKE_BOX_INDEX`.
- `multi_search()` + `_resolve_index_routing()` (`search_api.py:771`): `output_index=["puke-box"]` adds the `puke-box` index to the searched list (same shape as `SAMPLES_INDEX` at `search_api.py:802`).
- New searchable/filterable attributes: `scale`, `root`, `tempo`, `chords`, `entry_id`, `description`. Added to the shared settings; the puke-box index inherits them.

## Ingest (`server/pukebox_ingest.py` + `manage.py pukebox-ingest`)

Ports `ausupply.github.io/puke-box/scrape_midieval.py` (parse + download logic already proven over 138 entries) but writes to SQLite + Meilisearch instead of git. Reuses `slack_scraper` primitives (`slack_api`, `download_slack_file`, `_ingest_file`).

- `parse_midi_message()` — lifted as-is (regex matches the bot's `*Daily MIDI* — {scale} in {root} ({tempo} BPM)` header).
- Per new message: download 4 MIDI stems to `audio/YYYY-MM/`, synthesize OGG, create `MediaItem` + `MediaSource` + `MediaAudioMeta` + `MediaPukeBoxMeta`, sync to Meilisearch.
- Dedup by Slack thread ts (skip if `MediaSource.slack_message_ts` already exists).
- `manage.py pukebox-ingest` wraps it for server invocation (AGENTS.md #8 — no inline Python through `ssh dokku`).
- `manage.py pukebox-backfill` — one-shot: read `/srv/legacy-site/puke-box/` (138 existing entries with OGG + MIDI already on disk), create `MediaItem`s without re-downloading. Avoids re-scraping Slack (some old file attachments are gone — saw `0 MIDI files downloaded` for 2026-03-13 entries).

## Public page + API surface

- `src/pages/pukebox.astro` — public, `Base.astro` layout, mounts a `Pukebox.svelte` island.
- The island needs a **public** read endpoint. Today `/api/search` is admin-gated; `/api/public/outputs` (`search_api.py:1114`) is public but may not expose the fields the jukebox needs. Options (open question Q3):
  - Extend `/api/public/outputs?output_index=puke-box` to return the denormalized `MediaPukeBoxMeta` fields.
  - New narrow `GET /api/pukebox/manifest` → `[{id, date, scale, root, tempo, description, preview_url, midi_urls}]`, public, no auth.
- `/api/serve?output_index=puke-box&sort=random` already works for random track picking once the index exists.

## Open questions

- **Q1 — OGG synthesis.** The legacy scraper uses `midi-bot/src/synthesizer.py` + ffmpeg (lives in the other repo). Options: (a) vendor the synthesizer into this repo; (b) run synth as a bot job via `apps/*.toml` pointing at a midi-synth image; (c) skip server-side OGG and render the 4 MIDI stems client-side in the browser via Web Audio / a MIDI.js-style library. (c) is appealing — drops the ffmpeg/synth dependency and the OGG storage — but changes the playback model and the page becomes heavier.
- **Q2 — What schedules the ingest?** `slack_scraper` runs on a schedule (confirm where: worker cron vs Dokku cron vs GH Action). Puke-box ingest should ride the same mechanism, or run as its own `manage.py` cron on the server.
- **Q3 — Public read endpoint shape.** Extend `/api/public/outputs` or add a dedicated `/api/pukebox/manifest`? The dedicated endpoint is less generic but keeps the jukebox payload tight and stable.
- **Q4 — Aesthetic.** Keep the retro jukebox CSS (port `puke-box.html` styles into the Svelte island) or restyle to match the site's brutalist tokens (`docs/frontend.md`)? Legacy page stays either way.
- **Q5 — MIDI stem storage.** Store the 4 `.mid` files under `SEARCH_MEDIA_DIR/audio/YYYY-MM/` as regular media files (servable via existing `/api/serve`-style routes) and reference by path in `MediaPukeBoxMeta.midi_paths`, or keep them outside the media dir as "bag files" only downloadable through a puke-box-specific route?

## Out of scope

- Fixing the legacy webhook chain (the `/srv/legacy-site` git pull). The new page makes it irrelevant; legacy `/puke-box.html` stays frozen at its last-working state unless someone separately fixes the webhook + `safe.directory`.
- Removing `ausupply.github.io/puke-box.yml` or the `daily-midi` action. They keep running — the legacy page still consumes them.
- Voting / Acclaim-Disavow on puke-box entries (works for free via existing `MediaVote` machinery — just not designed around it yet).
