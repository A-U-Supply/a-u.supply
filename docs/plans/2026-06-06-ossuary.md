# Ossuary — RAVE-driven sound-design workstation

**Date:** 2026-06-06 (rev. per Tube review)
**Status:** Direction approved by Tube w/ constraints; doc revised for greenlight.
**Lives:** `/admin/atelier/ossuary` (admin-only Atelier tool)
**Codename:** an ossuary is a vault of bones. Carved hits are the bones; they go into
the shared library. Fits the skeletal motif of the rottengenizdat recipes.

> **Identity (firm):** Ossuary is a **quirky sound-design workstation that indexes
> weird samples into our search engine** — *not* a drum machine. **Litany is the drum
> machine.** Ossuary makes the strange one-shots that Litany (and any search client)
> later plays. **Ossuary does not know Litany exists** — no handoff, no shared audio
> engine, no beat pre-population. The real product is a clean stream of well-tagged
> samples flowing into `samples-bored`.

## Context — why this exists

`rottengenizdat` ("RGZ-9 Latent Space Press", `apps/rottengenizdat.toml`) already runs
RAVE models server-side as a queued bot, reached today only through **Hecatomb** (bulk,
async). There's no way to interpret one clip and design sounds from it.

A RAVE model is "a brain that has only ever heard one kind of sound" (percussion,
vintage, NASA, voices, …); handed any audio it re-hears it through that lens. Ossuary
turns that into a sound-design loop: feed a clip to a brain, it reorganizes the
material into transients, carve those into editable one-shots, shape them deeply (edit
+ FX + envelope), audition them, and **index them into `samples-bored`** with rich
metadata so they're discoverable everywhere.

## Pipeline

```
  pick clip ─▶ choose brain + knobs ─▶ [ONE rotten pass: server] ─▶ wet WAV
       │                                                               │
       │                                        onset/transient detect │  (browser)
       │                                                               ▼
       └──────────────────────────────────▶ slices ─▶ auto-classify into slots
                                                                       │
        per-hit: trim · normalize · fade · gain · reverse · tune(bake) · FX · envelope
                          · reassign slot · drop · audition         (all browser)
                                                                       │
                                  ┌────────────────────────────────────┤
                                  ▼                                     ▼
                     minimal audition loop                  INDEX → samples-bored
                  (1 track, BPM, onset-seeded)              (+ ZIP export convenience)
```

## 1. The interpreter (one rotten pass)

- **Brain picker** — manifest models: `percussion` (**default**), `vintage`, `nasa`,
  `VCTK`, `musicnet`, `isis`, `sol_ordinario`, `sol_full`, `darbouka_onnx`. Affects
  **both** the character of the hits and which hits are found.
- **Knobs** — manifest single-pass params: temperature, noise, dims, shuffle,
  quantize, reverse; plus a wet/dry `mix` knob + toggle (wet hallucination vs. clean
  cuts from the original at the found points).
- **One job at a time per client.** INTERPRET is disabled while a job is in flight;
  a skeleton-building animation runs during the wait (no partial streaming — RAVE is
  server-side). Don't like it? Re-INTERPRET with different knobs. **No per-slice
  reprocess** — keep the loop fast.

## 2. The editing surface — the star (all client-side)

After the single rotten pass, everything is instant and local:

- **Carve controls:** sensitivity / number of hits.
- **Per-hit editing:** trim in/out (with **waveform zoom + zero-crossing snap** to
  avoid clicks), **normalize**, **fade in/out**, gain, **reverse**, **pitch/tune**
  (bakes into export).
- **FX chain (core sound-design requirement):** delay, filter, reverb, EQ — previewed
  live, **baked on save**.
- **Rich envelope editing:** attack/decay (and beyond) with a **deeply tweakable
  shape** — wide exponential range, linear, log, in-between. The envelope is half the
  character.
- **Slots:** auto-classify on carve into Litany's vocabulary (`kick`, `snare`,
  `hi-hat`, … — `src/lib/litany/state.ts:166`); user can drag/reassign or drop freely.
  **No "complete kit" enforcement** — 10 kicks and no snares is valid; one sample is
  valid. The slot is just a searchable tag.
- **Own lightweight Web Audio playback** — isolated, minimal; **do not reuse Litany's
  engine/state**.

## 3. Minimal audition loop (not a sequencer)

Just enough to hear a sample triggered in context — **not** a beat generator.
- Single track, BPM, simple trigger pattern (Tube's "PLR-style sliders").
- **Default pattern seeded from the carved onset times** — the cheap nod to "hear it
  in the clip's own rhythm" without building a second sequencer. (Reconciles Brendan's
  "clip-derived rhythm" interest with Tube's no-sequencer rule.)
- No multi-track, no genre templates, no complex sequencing UI. Deep sequencing is
  Litany's job.

## 4. The real output: index into `samples-bored`

This is the product. Each carved+edited hit is uploaded and written as a MediaItem in
`samples-bored` (model on `scripts/index_samples.py`; schema in
`server/search_client.py`). The whole point: these live alongside everything else and
are discoverable by Litany and any search client through the same interface.

**Tags on every Ossuary output** (pick one source key, be consistent — using
`source:ossuary`):
- `source:ossuary`
- `slot:<kick|snare|hi-hat|…>`
- `model:<percussion|vintage|…>`
- `carved`
- `rave` / `rotten` / `rgz-9`
- relation back to the original clip's ID (source linkage) where possible

**Search doc fields to populate** (all real in `search_client.py`):
- `output_index`: `samples-bored`
- `tags`: as above
- `job_app`: `rottengenizdat`; `job_model`: chosen brain; `job_recipe`: `single_pass`
- `duration_seconds`, `sample_rate`, `channels`, `bit_depth` — from the carved WAV
- `description`: auto-generated + user-editable (e.g. "Carved kick from field
  recording via RGZ-9 percussion brain, tuned -3st")

Result: in Litany or any client, `source:ossuary slot:kick model:percussion` returns
exactly those weird kicks. **No dedicated `ossuary` collection; no Litany handoff in
Ossuary** — Litany already queries `samples-bored`; Tube adds a `source:ossuary`
filter/toggle in Litany **separately**.

- **ZIP export** is a *convenience* (reuses `search_api.py` multi-file ZIP) for
  external samplers. **ZIP-of-WAVs only for v1**; SFZ / Decent Sampler / hardware
  layouts deferred (Number4 can opine later — directive is defer).

## 5. UX, wait-feel, theming

- Single page, brutalist controls. Top: source picker + clip waveform. Left rail:
  brain + knobs + carve controls + big **INTERPRET** (disabled while job in flight).
  Center: carved hits (per slot — audition, zoom/trim, edit, FX, envelope, reassign,
  drop). Bottom: minimal audition loop (BPM + onset-seeded pattern). Action bar: Index
  to library · Download ZIP.
- **Wait must feel intentional, not broken:** skeleton-building animation during the
  rotten pass; after it, the user never waits on the server again until **Index to
  library**. (Bones-assembling GIF idea retained; finalize later.)
- **Page background: charcoal.** Register in `Admin.astro` (`applyPageBackground`).
- **Reproducibility (Atelier house rule):** save a JSON record on outputs (tool,
  source IDs, seed, params) + a seed + "shuffle seed" on anything random.

## 6. Inputs

- No typical length (~30s–2min common, plan for anything; rotten cost scales w/ length).
- **One clip per run for v1** (multi-clip kit building deferred).
- **Source priority:** Media Library picker → index search → random-pull → own-upload.

## 7. Architecture (Tube's corrections, locked)

- **Don't reuse Litany's audio engine** — Ossuary owns a minimal, isolated Web Audio
  player.
- **Client-side everything possible:** onset detection, slot classification, trim,
  gain/normalize/fade/reverse/tune previews, FX chains, envelope. The server only:
  (a) accepts the rotten job, (b) returns the wet WAV, (c) accepts the final carved
  WAVs for indexing.
- **One async wait, then instant interaction.**
- **No kit-library panel in v1** — search is the library (a panel is an easy v2 add if
  we find we need it).
- **Ossuary does not know Litany exists.**

## 9. Revised MVP (Tube's "first slice worth using")

1. **Scaffold** `/admin/atelier/ossuary` — charcoal bg, source picker, clip load +
   preview waveform.
2. **rotten pass** — single-input `rottengenizdat` submit + poll + fetch wet WAV +
   skeleton animation. One job at a time.
3. **Carve + classify** — browser onset detection, slot auto-classify, reassign/drop,
   waveform zoom + zero-cross snap.
4. **Edit** — trim, normalize, fade, gain, reverse, tune(bake) + **FX chain** (delay,
   reverb, filter, EQ) + **rich envelope**, previewed live, baked on save.
5. **Minimal audition loop** — single track, BPM, onset-seeded pattern.
6. **Index to `samples-bored`** — upload carved WAVs; write MediaItem + tags + search
   doc with full metadata.
7. **ZIP export** — convenience download; deferred behind #6 if time is tight.

**Explicitly NOT in MVP:** multi-track sequencing / beat generators / genre templates;
"Open in Litany"; kit-library panel; per-slice reprocess; multi-clip kits; SFZ/Decent
Sampler/hardware formats; reusing Litany's engine or state.

## 10. Build phases (separate PRs per AGENTS.md, after greenlight)

Phases map 1:1 onto the MVP steps above. Phase 1 = scaffold.

## 11. Verification (per phase)

- rotten pass returns a wet WAV for a real index clip within the job timeout; INTERPRET
  correctly locked while in flight.
- Carve yields sensible hits; auto-classify roughly right on a drum loop; reassign works.
- Edits + FX + envelope + tune bake correctly into the saved WAV.
- Indexed sample appears in search via `source:ossuary slot:kick model:<brain>` and
  plays in Litany (which already queries `samples-bored`).
- ZIP imports cleanly into an external sampler.
