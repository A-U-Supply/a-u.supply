# Ossuary — RAVE-driven sample-kit builder

**Date:** 2026-06-06
**Status:** Design draft for review (Tube)
**Lives:** `/admin/atelier/ossuary` (admin-only Atelier tool)
**Codename:** an ossuary is a vault of bones — a drum kit is a rack of hits/bones.
Fits the existing skeletal motif of the rottengenizdat recipes (Bone X-Ray, Skull
Radio, "percussive skeleton"). Saved kits are the relics.

> **North star:** the primary feature is **sound design** — a smooth, intuitive
> surface for *selecting, editing, and populating* samples carved out of a clip. The
> auto-beat is a core-but-lightweight bonus; deep sequencing control belongs to
> Litany. Every priority call below bends toward making the carve/edit/curate loop
> feel great.

## Context — why this exists

`rottengenizdat` ("RGZ-9 Latent Space Press", `apps/rottengenizdat.toml`) already
runs RAVE models server-side as a queued **bot**, reached today only through
**Hecatomb** — bulk, fire-and-forget, async. There's no way to *interpret one clip
and listen.*

A RAVE model is "a brain that has only ever heard one kind of sound" (percussion,
vintage vinyl, NASA, voices, …). Handed any audio, it re-hears it through that lens.
Ossuary turns that single-mindedness into a tool: feed a clip to the percussion brain
and it reorganizes the material into drum-like transients; detect those transients and
you've carved a drum kit — the hits the model *heard*. Add a model picker, knobs, a
fast edit surface, a light auto-beat, and a tagged export that Litany can load.

## Pipeline

```
  pick clip ──▶ choose brain + knobs ──▶ [RAVE pass: server bot] ──▶ wet WAV
       │                                                                 │
       │                                          onset/transient detect │  (browser)
       │                                                                 ▼
       └────────────────────────────────────────────▶ slices ──▶ classify into slots
                                                                         │
                              audition / trim / normalize / fade / gain / reverse / tune
                                          / reassign / drop / layer        (browser)
                                                                         │
                                  ┌──────────────────────────────────────┤
                                  ▼                  ▼                    ▼
                          auto-generate beat   export pack (ZIP)   save kit (tagged)
                                  │                                       │
                                  └──────────▶ "Open in Litany" ◀─────────┘
```

## 1. The interpreter (RAVE pass)

- **Brain picker** — dropdown over the manifest models: `percussion` (**default**),
  `vintage`, `nasa`, `VCTK`, `musicnet`, `isis`, `sol_ordinario`, `sol_full`,
  `darbouka_onnx`. The model choice matters for **both** the *character* of the hits
  and *which* hits get found.
- **Knobs** — the single-pass params already in the manifest: temperature, noise,
  dims, shuffle, quantize, reverse.
- **Wet/Dry** — a `mix` **knob plus a quick toggle**. Decides whether the carved
  samples *sound like the model's hallucination* (wet), are taken clean from the
  **original clip at the cut points the model found** (dry), or a blend. Default wet
  (the whole point), one tap to dry.
- Mechanism confirmed: the model reorganizes energy into transients; onset detection
  on the **wet** signal yields the cut points → "the interpretation drives the
  selection."

## 2. The editing surface — the star

Per-hit, all browser-side (instant) after the one RAVE pass:

- **Carve controls:** sensitivity / number of hits / per-slot count.
- **Edit each hit:** trim in/out, **normalize**, **fade in/out**, gain, **reverse**,
  **pitch/tune** — and **pitch/tune bakes into the exported WAV** (not just a playback
  setting).
- **Multiple samples per slot** when enough valid hits map to it (round-robin /
  layers).
- Reassign a hit to another slot; drop a hit.
- Waveform view; see [Questions for Tube] re: zoom + zero-crossing snap.

## 3. The auto-beat (core but light)

- **Generator dropdown:** Euclidean · genre templates · random · **derived from the
  clip's own rhythm (default)** — replay the timing the model heard.
- A *few* knobs only (e.g. density / swing). No deep sequencing here — that's Litany.
- Inline play/stop + **Regenerate**. Seeded (see reproducibility).

## 4. Kit library + Litany handoff

- **Little library** of saved kits as a **browse/load panel inside the Ossuary page**
  (not a separate sidebar entry) — load a past bone-vault in one click.
- **Save kit → server, tagged:** each sliced hit becomes a media item in a collection
  Litany reads, tagged `app:ossuary`, `kit:<slug>`, `slot:<kick|snare|…>`,
  `model:<name>`, `source:<id>`. Reuses the existing job-output tagging shape
  (`jobs_api.py` auto-tags `app:/model:/index:` + user tags).
- **Open in Litany:** auto-populate **one Litany voice per non-empty slot**, each
  querying `kit:<slug> slot:<name>`, with the **generated beat's steps pre-filled**.
  (Confirm mapping with Tube.) Searching the index for individual hits to pin still
  works like any other sample.

## 5. Export

- **Baseline: ZIP of named WAVs** (universal; reuses `search_api.py` multi-file ZIP
  export). Naming like `kick_01.wav`, `snare_01.wav`, …
- Other formats (SFZ / Decent Sampler / hardware layouts) and sample-rate/bit-depth/
  channel decisions → see [Questions for Tube].

## 6. Reuse map (low new-surface)

| Need | Reuse |
|------|-------|
| RAVE interpretation | `rottengenizdat` bot, `single_pass` mode, existing knobs |
| Single-input job submit + poll | `jobs_api.py` job endpoints (not Hecatomb bulk) |
| Instant browser playback | Litany Web Audio engine (`src/lib/litany/audio.ts`) |
| Tagged, discoverable outputs | job-output auto-tags + user tags |
| Litany discovery | Litany already queries `output_index=…&query=…` |
| ZIP pack download | `search_api.py` multi-file ZIP endpoint |
| Beat editing | Litany (hand off via its URL state encoding) |

**Genuinely new:** the Atelier page; browser onset detection + slot classification;
the edit/curate UI; the light beat generator; pack-format writers (if chosen).

**Architectural note:** Ossuary is the **first Atelier tool that depends on a server
bot pass mid-flow.** Photism/Litany are pure-browser; Punctum ports bot algorithms to
TS. Ossuary instead *orchestrates* a real `rottengenizdat` single-pass job, then does
carve/classify/edit/beat client-side — one async wait, then Litany-fast interaction.

## 7. UX, wait-feel, theming

- Single page, brutalist controls. Top: source picker + clip waveform. Left rail:
  brain + knobs + carve controls + big **INTERPRET** button. Center: carved kit
  (pads/rows per slot, each a slice waveform — click to audition, drag to trim,
  reassign, layer, drop). Bottom: beat strip + Regenerate. Export bar: Save · Download
  pack · Open in Litany. Side: kit-library load panel.
- **The wait must feel near-instant.** Minimize round-trips; during any RAVE pass /
  load show a **cute animated GIF** — first pass: *bones assembling* (open to change
  once we see options). Tube owns the actual to/from-server logistics.
- **Page background: charcoal.** Register in `Admin.astro` (`applyPageBackground`).
- **Reproducibility (Atelier house rule):** save a JSON record on outputs (tool,
  source IDs, **seed**, params) and expose a seed + "shuffle seed" on anything random
  — applied to **both** the carve and the beat-gen, so any kit/beat is reproducible.

## 8. Inputs

- No typical length — a Slack-scraped sound, a whole song, or a field recording are
  all fair game; **~30s–2min common but plan for anything** (the RAVE-pass cost scales
  with length; expect long inputs).
- **One clip → one kit** for v1 (Tube may revise — see questions).
- **Source priority:** Media Library picker → index search → random-pull → own-upload.

## 9. Questions for Tube (consolidated)

1. **Slots model:** fixed slots (KICK/SNARE/HAT/…) with auto-classification, vs. N
   raw slices the user assigns by hand? And how good can auto-classify realistically
   be — your call on feasibility.
2. **Per-slice reprocess:** allow sending a *single* hit back through a *different*
   brain (e.g. snare → VCTK)? Brendan wants it if it's not too costly — your read on
   difficulty / round-trip cost.
3. **Waveform zoom + zero-crossing snap** (snapping cut points to where the waveform
   crosses zero, to avoid clicks): in scope, and how hard?
4. **One clip → one kit** vs. pulling hits from several clips into one kit — you may
   feel differently; pick what's sane.
5. **Export format priority** beyond ZIP-of-WAVs (SFZ? Decent Sampler? MPC / Dirtywave
   M8?), plus sample rate / bit depth / mono-vs-stereo. **If you're unsure, ask
   Number4.**
6. **Naming / sub-vocabulary** (the act of carving, a hit, the kit, the slots): your
   call — keep it consistent and **non-confusing** alongside existing and future
   server bots. ("Carve" is a candidate verb.)
7. **Wait/logistics:** how to make the RAVE pass *feel* near-instant — short-clip
   caps, pre-warming, streaming, queue priority for single-input jobs?
8. **Kit collection:** write into the existing `samples-bored` collection with
   `kit:`/`slot:` tags, or a dedicated `ossuary` collection that Litany also queries?
9. **Litany auto-populate mapping** (one voice per non-empty slot + beat steps) —
   confirm it fits Litany's current voice/state model.

## 10. MVP cut-line (agreed) + phases

**MVP (first slice worth using):** pick clip → INTERPRET (percussion) → carved pads
you can audition / trim / reassign → save kit + Open in Litany. Beat-gen and richer
export follow immediately after.

Build phases (separate PRs per AGENTS.md, once greenlit):
1. Scaffold `/admin/atelier/ossuary`: source picker, clip load/preview, charcoal bg.
2. RAVE pass: single-input `rottengenizdat` submit + poll + fetch wet WAV + loading GIF.
3. Carve + classify + edit/curate UI (onset detection, slots, trim/normalize/fade/
   gain/reverse/tune-bake, multi-per-slot).
4. Beat generator (dropdown, clip-derived default, few knobs) + inline audition.
5. Export: tagged save-to-server, kit library panel, ZIP pack, Open-in-Litany.
6. Litany: surface the kit collection as a selectable source + auto-populate.

## 11. Verification (per phase)

- RAVE pass returns a wet WAV for a real index clip within the job timeout.
- Carve produces sensible hits; slot classification roughly right on a drum loop.
- Pitch/edit bakes correctly into exported one-shots.
- Saved kit appears in search filtered to its collection + `kit:<slug>`, and Litany
  loads/plays it with the beat pre-filled.
- Downloaded ZIP imports cleanly into a sampler.
